# 01 需求文档 — 随手笔记（QuickNotes）

> 版本 v1.0 · 2026-11-17 · 状态：待评审
> 关联：`PLAN.md`（决策表 D1–D14）、`02-UI-UX设计文档.md`、`03-架构设计文档.md`、`04-数据模型文档.md`

## 1. 产品定位

一款 Windows 桌面端的**轻量速记工具**。形态是桌面常驻的悬浮球，点开就是一个能直接写 Markdown 的小面板；笔记以**纯 .md 文件**存在用户指定的目录里，不锁进数据库、不依赖云。附带**完全离线的本地 AI**（润色/续写/标题摘要/语义检索），并且**必须能在低配电脑上正常使用**——AI 不达标就自动降级或关闭，绝不把机器拖卡。

一句话：**随手一按就能记，记下的东西永远是能拿走的纯文本文件。**

## 2. 目标用户与硬件画像

| 画像 | 配置 | 产品要求 |
|------|------|---------|
| 主流 | 16GB 内存 + 独显 | 全部功能可用，可用 1.5B 模型 |
| 低配 | 8GB 内存 + 核显 | 全部功能可用，AI 用 0.6B 模型，纯 CPU |
| 极低配 | 4GB 内存 / 老双核 | **笔记功能正常**；AI 默认禁用并置灰说明原因 |

**硬性约束**：
- 4GB 机器上不得因 AI 导致整机卡顿（Win10/11 自身占 2–2.5GB，Electron+模型峰值 1.1–1.3GB 会触发页面文件抖动）。
- 老 CPU（仅 AVX2，如 i3-6100）必须能运行，不得出现 `illegal instruction` 崩溃。
- Intel 核显的 Vulkan 后端不得默认启用（已知崩溃与负优化）。

## 3. 功能需求

### FR-1 悬浮球（P0）

| 编号 | 需求 | 验收标准 |
|------|------|---------|
| FR-1.1 | 桌面常驻悬浮球 | 启动后球出现在鼠标所在屏幕工作区内，距右边缘 8px、垂直居中；尺寸 56×56 DIP |
| FR-1.2 | 拖动与吸边 | 拖动无延迟跟手；松手时球心距屏幕边缘 <12px 则吸附到边缘 |
| FR-1.3 | 半透明 | 默认不透明度 0.85，鼠标悬停时变为 1.0（150ms 过渡） |
| FR-1.4 | 点击展开面板 | 单击球展开笔记面板；面板从球所在一侧滑出，箭头指向球 |
| FR-1.5 | 失焦收起 | 面板失焦 300ms 后收起；若编辑器有未保存内容，改为保留并显示"未保存"标记 |
| FR-1.6 | 位置记忆 | 记录多显示器下的 DIP 坐标；重启后若坐标不在任何屏幕工作区内，回落到主屏右侧 |
| FR-1.7 | 多显示器与 DPI | 监听 `display-metrics-changed`；跨屏切换或缩放变化后球不跑出屏幕 |
| FR-1.8 | 右键菜单 | 右键球弹出：新建笔记 / 打开面板 / 打开笔记目录 / 设置 / 退出 |

### FR-2 托盘与全局热键（P0）

| 编号 | 需求 | 验收标准 |
|------|------|---------|
| FR-2.1 | 托盘图标 | 常驻托盘，图标与悬浮球一致 |
| FR-2.2 | 托盘菜单 | 五项固定：新建笔记、显示/隐藏面板、打开笔记目录、设置、退出 |
| FR-2.3 | 全局热键 | `Ctrl+Alt+N` 新建并唤出面板（避开 OneNote 占用的 Win+Alt+N）；热键被占用时提示可改 |

| FR-2.5 | 开机自启 | 设置项开关，默认关；开启后以 `--hidden` 参数启动（只起球和托盘，不弹面板） |

### FR-3 编辑器（P0）

| 编号 | 需求 | 验收标准 |
|------|------|---------|
| FR-3.1 | 源码编辑 | 使用 CodeMirror 6，Markdown 语法高亮 |
| FR-3.2 | 实时预览 | **自适应渲染延迟**（用户 2026-11-17 拍板，取代原固定 120ms）：以 120ms 为目标值，运行时按实测渲染耗时自动调整防抖窗口——连续 5 次渲染的中位耗时 ≤40ms 则窗口 120ms；40–120ms 则窗口取「中位耗时 ×3」；>120ms 则窗口 400ms 并在状态栏提示「低配模式：预览稍慢」。窗口值上限 400ms、下限 100ms，随机器负载动态收敛，落盘记住上次值。渲染结果经 DOMPurify 净化 |
| FR-3.3 | 自适应布局 | 面板宽度 <520px 单栏（编辑/预览 Tab 切换）；520–900px 上下分栏；>900px 左右分栏；分栏比例记忆。**默认体验**：启动为 480px 宽 → 落 <520 区间 → 即默认单栏 Tab 切换（与 02 §4 一致）；用户自行拖宽后才进入分栏 |
| FR-3.4 | 滚动同步 | 按"源码行→渲染块"锚点映射，非像素比例；用户手动滚动后暂停同步 1.5s |
| FR-3.5 | 自动保存 | 停止输入 800ms 后写盘；状态栏显示"已保存/保存中/未保存" |
| FR-3.6 | 状态栏 | 显示字数、字符数、光标行列、保存状态 |

### FR-5 文件与目录管理（P0）

| 编号 | 需求 | 验收标准 |
|------|------|---------|
| FR-5.1 | 首次启动引导 | 弹出目录选择，默认 `%USERPROFILE%\Documents\QuickNotes`；未确认目录前不创建任何笔记 |
| FR-5.2 | 新建笔记 | 文件名 `YYYY-MM-DD-HHmm.md`，冲突则加 `-2`；若首行为 `# 标题`，保存时询问是否改名为 `标题.md` |
| FR-5.3 | 打开已有 | 目录树浏览 + 文件选择器；只允许打开笔记目录内的 `.md` |
| FR-5.4 | 重命名 | 在目录树内联重命名，校验非法字符与重名 |
| FR-5.5 | 删除 | 移入笔记目录下 `.trash/`（不直接删），带确认；`.trash` 在目录树中隐藏 |
| FR-5.6 | 目录树 | 显示子目录与 `.md` 文件，忽略隐藏目录、`node_modules`、`assets`、`.trash` |
| FR-5.7 | 最近打开 | 记录最近 20 篇，按时间倒序 |
| FR-5.8 | 外部变更 | 使用 `chokidar`（4.0.3）监听笔记目录；外部修改/删除/新增后刷新目录树；当前打开文件被外部改动时提示"文件已在外部变更"并允许重新加载 |
| FR-5.9 | 切换目录 | 设置中可改；**只切索引，不移动/不迁移已有文件**；原目录文件保持不动 |
| FR-5.10 | 编码与换行 | 统一 UTF-8；保留文件原有换行风格（CRLF/LF），新文件用 CRLF |

### FR-6 搜索与标签（P0）

| 编号 | 需求 | 验收标准 |
|------|------|---------|
| FR-6.1 | 文件名搜索 | 输入即时过滤目录树，≤50ms |
| FR-6.2 | 全文检索 | MiniSearch 7.2.0 + `Intl.Segmenter` 中文分词（不引入需编译的 nodejieba）；1000 篇×2KB 场景：索引构建 1.1–1.7s，单词查询 <1ms |
| FR-6.3 | 索引增量 | 按 mtime 增量更新；索引落盘为单 JSON（约 4.5MB/1000 篇），启动反序列化约 25ms；索引存放于 `%APPDATA%\QuickNotes\index\`，**不写入笔记目录** |
| FR-6.4 | 结果展示 | 显示标题 + 命中片段高亮 + 路径；回车打开并定位到首个命中 |
| FR-6.5 | 标签 | frontmatter（`tags: [a, b]`）为主 + 正文 `#tag` 为辅；行内标签解析前须剥离围栏代码块；标签面板可点选过滤 |
| FR-6.6 | frontmatter 解析 | 用 `js-yaml` 5.5.0 自切 `---` 边界（不依赖停更的 gray-matter） |

### FR-7 本地 AI（P1，可关闭）

| 编号 | 能力 | 规格 |
|------|------|------|
| FR-7.1 | 润色选中 | 选中文本 → 菜单"润色"，结果在浮层预览，可选择替换/追加/丢弃 |
| FR-7.2 | 续写 | 光标处按上下文续写，流式输出，Esc 中止 |
| FR-7.3 | 生成标题/摘要 | 依据全文生成标题候选与 1–3 句摘要 |
| FR-7.4 | 语义检索 | 用 nomic-embed-text-v1.5 建向量索引，与全文检索并列展示（"相关"标签页） |
| FR-7.5 | 流式与中止 | 所有生成任务流式返回；随时 Esc 中止；中止后不留下半截内容到笔记 |
| FR-7.6 | 硬件门禁 | 读 `os.totalmem()`：<8GB 默认禁用 AI，设置项置灰并说明原因；≥8GB 自动选 0.6B 档；≥16GB 且用户可选 1.5B 档 |
| FR-7.7 | GPU 策略 | 默认 `gpu:false` 纯 CPU；仅当检测到 NVIDIA/AMD 独显且 VRAM≥4GB 才尝试 GPU；首次推理加 8s 超时，tok/s 低于 CPU 基线则回滚并记住 |
| FR-7.8 | 模型按需下载 | 模型不随精简版发布；首次启用 AI 时下载，走 ModelScope（有官方 sha256 校验）；显示进度、支持断点续传与取消；下载失败给出可读原因与手动放置说明 |
| FR-7.9 | 完全关闭 | 设置中可彻底关闭 AI：不加载推理库、不占内存、不显示相关入口 |

### FR-9 打包与分发（P0）

| 编号 | 需求 | 验收标准 |
|------|------|---------|

## 4. 非功能需求

| 编号 | 类别 | 要求 |
|------|------|------|
| NFR-1 | 冷启动 | 精简版 ≤3s 到悬浮球可用（不含模型） |
| NFR-2 | 内存 | 空闲≤300MB；启用 0.6B 模型后增量≤1.2GB |
| NFR-3 | 安全 | `contextIsolation:true`、`sandbox:true`、显式 CSP（`script-src 'self'`，预览禁 `unsafe-inline` script）；renderer 不得直接访问 `fs`；所有 IPC 走 preload 的 `contextBridge` 一事一接口 |
| NFR-4 | 数据安全 | 笔记目录为唯一事实源；删除走 `.trash`；索引与配置存 `%APPDATA%`；**不写任何笔记内容到配置文件** |
| NFR-5 | 隐私 | 零联网（除用户主动触发的模型下载）；不采集遥测；不发任何分析数据 |
| NFR-6 | 兼容 | Windows 10 1903+ / Windows 11，x64；仅 AVX2 的老 CPU 可运行 |
| NFR-7 | 中文 | 界面全中文；文件路径与内容支持 GB 级路径长度外的常规中文路径 |

## 5. 明确不做（v1 范围外）

标签的层级体系（`a/b/c` 仅作字面标签）、双向链接图谱、多标签页编辑、导出 PDF/HTML、云同步、移动端、插件系统、多语言界面、代码签名、自动更新（无签名下 `electron-updater` 会因 Authenticode 校验失败，v1 不做）。

## 6. 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 打包漏配 `asarUnpack` 导致原生模块找不到 | AI 全功能不可用 | 打包后真机冷启动验证 + 明确 `externals` 配置 |
| `@node-llama-cpp/win-x64` 未含 `ggml-cpu-x64.dll` 基线版 | 老 CPU `illegal instruction` 崩溃 | 安装后解压检查 DLL 变体；缺失则换 llama-server sidecar 方案 |
| Intel 核显 Vulkan 崩溃/负优化 | 用户机器上卡死 | 默认 `gpu:false`；仅白名单启用 |
| 4GB 机器强行开 AI | 整机卡顿 | 内存硬门禁 + 置灰说明 |
| 无签名触发 SmartScreen | 用户不敢装 | 文档明示；提供 portable 免安装版 |
| 中文分词质量 | 检索命中差 | `Intl.Segmenter` 已验证切分合理；失败可降级为字面 + 拼音首字母兜底（v2） |

## 7. 验收口径

1. 三档硬件各跑一遍：4GB（笔记可用、AI 置灰）、8GB（AI 可下载 0.6B 并完成四项任务）、16GB+（可选 1.5B）。
2. FR-4.1–FR-4.11 每条都必须有可复现的手动操作步骤与截图证据。
3. 笔记文件用系统记事本与 VS Code 打开后内容一致（证明是纯文本、无私有格式）。
4. 全程断网除模型下载外无任何外发请求（用系统级网络监控核验）。
