# 04 数据模型文档 — 随手笔记（QuickNotes）

> 版本 v1.0 · 2026-11-17 · 状态：待评审
> 关联：`01-需求文档.md`（FR-5/FR-6/FR-7/NFR-4）、`PLAN.md`（D6/D9/D12/D14）、`03-架构设计文档.md`
> 约定：`<ROOT>` = 用户笔记目录（默认 `%USERPROFILE%\Documents\QuickNotes`，可切换）；`%APPDATA%` = `…\AppData\Roaming`；`%LOCALAPPDATA%` = `…\AppData\Local`。

## 0. 第一原则

**笔记正文的唯一事实源是 `<ROOT>` 下的纯 `.md` 文件。** 不存在保存正文的私有数据库；本文其余结构化数据都是派生缓存或运行期状态——删掉 `%APPDATA%\QuickNotes` 全目录，笔记一条不丢，只损失检索速度与界面偏好。三条硬规则：

1. **可重建性分级**：笔记文件不可重建（P0）；索引/向量/草稿可重建；配置可回落默认值（设置会丢）。
2. **目录权属分离**：`<ROOT>` 只允许 `.md`、`assets/`、`.trash/`，应用不得在笔记目录写索引或隐藏元数据（NFR-4、FR-6.3）。
3. **写入即原子**：非笔记文件一律"临时文件 + fsync + rename"。

## 1. 存储分层总览

| 层 | 绝对路径 | 格式 | 可重建 | 体积估算（1000 篇 × 2KB 基准） |
|---|---|---|---|---|
| 笔记文件 | `<ROOT>\**\*.md` | UTF-8 无 BOM 纯文本 | **否（唯一事实源）** | 约 2 MB，不设上限 |
| 附件 | `<ROOT>\assets\YYYYMMDD-HHmmss.png` | PNG/JPEG/WebP 原字节 | 否（用户数据） | 约 100 KB/张 |
| 磁盘索引 | `%APPDATA%\QuickNotes\index\<rootHash>\search-index.json` | JSON（MiniSearch `toJSON()` + 包装） | 是（重建 1.1–1.7 s） | **约 4.45 MB**；反序列化约 25 ms |
| 向量索引 | 同上目录 `vectors.bin` + `vectors.meta.json` | Float32 定长二进制 + JSON 元数据 | 是（需重新推理） | 约 9.2 MB（3000 chunk × 3072 B）+ 元数据 0.3 MB |
| 配置文件 | `%APPDATA%\QuickNotes\config.json` | JSON（UTF-8 无 BOM） | 是（回落默认） | < 32 KB |
| 日志 | `%APPDATA%\QuickNotes\logs\main-YYYYMMDD.log` | 纯文本行 | 是（可直接删） | 约 0.5 MB/天，7 天 ≤ 3.5 MB |
| 崩溃草稿 | `%APPDATA%\QuickNotes\drafts\<sha1(相对路径)[:16]>.json` | JSON（含正文快照） | 是（临时件） | ≤ 50 份 |
| 模型文件 | `%LOCALAPPDATA%\QuickNotes\models\<modelId>\` | GGUF + `verify.json` | 是（重下或复制） | 精简版 378 MB + 84 MB；完整版另含 940 MB |
| 回收站 | `<ROOT>\.trash\<YYYYMMDD>\<原相对路径>` | 同笔记格式（原字节移动） | 否（用户数据，30 天） | ≤ 笔记总量 10% |

模型放 `%LOCALAPPDATA%` 而非 `%APPDATA%`：`Roaming` 在域环境会同步到服务器，1.3 GB 会拖垮登录；几 MB 的配置与索引留 `Roaming` 便于备份，也正合 NFR-4。`<rootHash>` = `sha1(规范化小写 ROOT).slice(0,12)`，支撑 FR-5.9"切目录只切索引"：每根一套命名空间，切回即用，保留最近 3 套（`builtAt` LRU）。

## 2. 笔记文件规范

### 2.1 文件名规则

| 场景 | 规则 | 示例 |
|---|---|---|
| 新建（FR-5.2） | `YYYY-MM-DD-HHmm.md`，本地时间，24 小时制补零 | `2026-11-17-2231.md` |
| 同分钟重名 | 追加 `-2`、`-3`…（探测到空位，上限 `-99`） | `2026-11-17-2231-2.md` |
| 首行为 `# 标题` | 保存后**询问**是否改名 `标题.md`，拒绝则不改 | `周会要点.md` |
| 标题改名归一化 | 去首尾空白 → 非法/控制字符换 `-` → 合并连续 `-` → 去尾部 `.` 与空格 → ≤ 80 字符 → 命中保留名加 `_` → 目标已存在加 `-2`，**绝不覆盖** | `周会-要点_2026Q4.md` |
| 重命名（FR-5.4） | 同上校验；保留扩展名大小写；不改子目录 | — |
| 目录树扫描 | 只认 `.md`（忽略大小写）；跳过隐藏目录、`node_modules`、`assets`、`.trash`（FR-5.6） | — |

**允许字符集**：新建归一化为「中日韩文字、拉丁字母、数字、空格、`-` `_` `( )`」；已存在文件含其它合法字符照常读写，不强制改名。

**Windows 非法字符清单**（新建与改名共用校验器，写入前拦截）：`< > : " / \ | ? *`；控制字符 U+0000–U+001F；结尾的 `.` 与空格（会被静默截断）；保留设备名 `CON` `PRN` `AUX` `NUL` `COM1`–`COM9` `LPT1`–`LPT9`（含带扩展名形式，`CON.md` 同样非法）；`<ROOT>` + 相对路径 ≤ 250 字符。

### 2.2 编码与换行

保存一律 **UTF-8 无 BOM**（读到 `EF BB BF` 时剥离并标记，保存不再写）。非法 UTF-8 → 试 UTF-16 LE/BE（`FF FE`/`FE FF`）→ 再试 `gbk`；后两者**只读打开**并提示"将以 UTF-8 另存"，用户确认才写盘（防静默损坏中文老文件）。换行（FR-5.10）：统计 `\r\n` 与裸 `\n` 占比，**保留原风格**，新文件 CRLF，编辑器内部统一 `\n`、写盘按主风格还原；混合换行统一为占比更高者并记一次日志。末尾空行不自动增删。大小：≤1 MB 舒适，>2 MB 提示拆分，>8 MB 不进索引（仍可编辑）。

## 3. frontmatter schema

边界：去 BOM 后第 1 行须为 `---`，且文件头 4 KB 内有闭合 `---` 才算 frontmatter，否则整个文件按正文处理（首行 `# 标题` 的普通笔记不受影响）；上限 64 行 / 4 KB。

| 字段 | 类型 | 必填 | 默认值 | 示例 | 说明 |
|---|---|---|---|---|---|
| `title` | string | 否 | 首个 `# ` 标题；无则文件名 | `title: 周会要点` | 仅作文档标题，不参与改名 |
| `tags` | string[] | 否 | `[]` | `tags: [工作/项目, 会议]` | 行内数组与块列表均可，与正文 `#tag` 合并 |
| `created` | string（ISO 8601 带时区） | 否 | `ctime` | `created: 2026-11-17T22:31:00+08:00` | 外层缺失才补写 |
| `updated` | string（同上） | 否 | `mtime` | `updated: 2026-11-17T22:40:12+08:00` | 保存成功后更新（可关） |
| `pinned` | boolean | 否 | `false` | `pinned: true` | 优先于最近打开排序 |
| 自定义字段 | 任意 YAML | 否 | — | `owner: 我` | **原样保留**：只改写托管字段区间的文本，其余顺序/缩进/注释/引号逐字节保留 |

**YAML 解析失败降级**（`js-yaml@5.5.0` 解析、自切 `---`，FR-6.6）：① 不抛错、不弹框、**不改文件**，整段按正文显示与索引；② 索引记 `fm:{ok:false, code, line}`（只记码与行号，不记 YAML 内容），标签改取正文 `#tag`；③ 编辑器顶部可关闭横幅"frontmatter 无法解析（第 N 行），已按正文处理"；④ 用户未编辑该区则原字节写回，保证"降级不破坏原文"；⑤ 校验重复键、tab 缩进、`tags` 非数组（是字符串时按单元素数组容忍）。

## 4. 行内标签规范

### 4.1 解析流程（顺序不可颠倒）

1. **剥离围栏代码块**：逐行状态机识别 ` ```{3,} ` / `~~~{3,}` 开闭（长度与语言标记需匹配），整块替换为**等长空白**（保留换行与字节偏移供高亮定位）。
2. **剥离行内代码**：`` /(`+)((?:(?!\1)[\s\S])*?)\1/g `` → 等长空白。
3. **掩码 URL 与实体**：`/(?:https?:\/\/|ftp:\/\/|mailto:|www\.)[^\s<>()\[\]"'）】]+/gi` 及 `&#\d+;`、`&#x[0-9a-f]+;`。**URL 锚点 `https://x.com/a#section` 的 `#` 永不成为标签。**
4. **粗筛正则**（Unicode 属性类，`u` 标志）：

```js
const TAG_RE = /(?<![\p{L}\p{N}_&/#\\:])#([\p{L}\p{N}_][\p{L}\p{N}_\-/]{0,63})/gu;
```

5. **前置边界复核**：`#` 前须为行首、空白/U+3000、中文标点（`，。、；：！？）》」』】`）、左括号（`([{（【`）、引用/强调符（`> * _ ~ -`）之一，否则丢弃（拦住 `a#b`、`C#`、`foo/#bar`）。
6. **尾部修剪**：去末尾 `/` 与 `-`；单标签 ≤ 64 字符；`#` 后紧跟空白不算标签（天然排除 Markdown 标题）。
7. 只作用于正文（frontmatter 已切走），不解析围栏语言标记行。

### 4.2 去重与大小写

归一化 = `normalize('NFC')` → 去首尾空白 → `toLowerCase()`（拉丁折 case，中文无影响）；**比较用归一化值，显示用首次出现的原始写法**。`frontmatter.tags` 与正文 `#tag` 合并去重，前者胜出（保留写法与顺序），正文标签按出现顺序追加。索引存 `tags`（归一化）与 `tagLabels`（归一化→原始），面板显示后者。`a/b/c` 仅作字面标签（不做层级体系）但必须允许 `/`：`#工作/项目` 与 `#工作` 是两个标签。

## 5. 索引模型（MiniSearch 7.2.0）

### 5.1 字段定义

| 字段 | index | store | boost | 说明 |
|---|---|---|---|---|
| `title` | ✅ | ✅ | **3.0** | frontmatter.title / 首个 H1 / 文件名 |
| `tags` | ✅ | ✅ | **2.0** | 归一化标签（join 空格后分词） |
| `headings` | ✅ | ❌ | **1.2** | 所有 `#`–`######` 文本 |
| `body` | ✅ | ✅ | 1.0 | 正文；代码块 token 加 `c:` 前缀，查询侧降权 0.3 |
| `path` | ❌ | ✅ | — | 相对 `<ROOT>`，用于展示/打开 |
| `mtime` / `size` | ❌ | ✅ | — | 增量双判据 |
| `fm` | ❌ | ✅ | — | frontmatter 解析状态 |

`searchOptions`：`{ prefix: true, fuzzy: 0.2, combineWith: 'AND', boost: { title: 3, tags: 2, headings: 1.2 } }`。代码块降权避免 `function`、`const` 把代码笔记顶到最前。

### 5.2 分词器要点

- `new Intl.Segmenter('zh-Hans', { granularity: 'word' })`，**`granularity` 必须 `'word'`**（`'grapheme'` 切单字、`'sentence'` 切整句，都不可用）。
- 取 `segments` 中 `isWordLike === true` 的段；拉丁词小写；长度 1 的汉字保留（中文单字查询需要）。
- **中英混排**：`React组件` 切成 `React` + `组件`，正合预期；`v1.2.3` 保留整 token 并追加 `v1`/`1`/`2`/`3` 支持前缀命中。
- 查询侧**复用同一实例**，保证 doc/query token 空间一致，否则中文召回必然错位。
- **停用词表：不需要。** ① 倒排 + TF-IDF 式打分，停用词不减体积也不改排序质量；② 笔记普遍几百字，删"的/了/是"显著降召回；③ 通用语料停用词对个人笔记属过度设计。替代手段：`combineWith:'AND'` + 字段 boost + 结果上限 50。

### 5.3 索引 JSON 结构（`search-index.json`）

```json
    "tags": ["工作/项目", "会议"], "tagLabels": { "工作/项目": "工作/项目" },

```

`body` 进 `storedFields` 是刻意取舍：索引涨到 4.45 MB（可接受），换来**生成命中片段不必回读磁盘**——召回 50 条省 50 次 I/O，文件被外部改动时片段仍与索引一致。

### 5.4 增量更新（mtime + size 双判据）

```
for each .md under <ROOT>（跳过 .trash/assets/node_modules/隐藏目录）:
  st = stat()                                  # 单次 stat，不读内容
  old = docsByPath[rel]
  if !old:                         → addDocument(读文件)
  else if st.mtimeMs !== old.mtime || st.size !== old.size:
        if |st.mtimeMs - indexWriteMs| < 2000: # mtime 落不可信窗口（同步盘/批量解压抹平）
            if quickHash(前4KB + 后4KB) === old.quickHash: 跳过
        → discard(old.id) 后 addDocument
  # 遍历后：docs 中存在但磁盘已消失 → discard
```

双判据的必要性：只比 mtime 会漏"同秒内改大小"（FAT 秒级时间戳、云同步回写），只比 size 会漏等长改写。`chokidar` 4.0.3 事件后 300 ms 防抖批量落盘，避免拖动保存时反复写 4.45 MB。单篇重索引约一次 readFile + 分词（2 KB < 2 ms），全量 1000 篇 1.1–1.7 s。

### 5.5 版本号与重建

索引同时记 `formatVersion`（包装结构）、`engine`（`minisearch@x.y.z`，序列化格式随库变）、`tokenizer`（分词规则变则旧 token 空间失效）、`root`/`rootHash`（防串目录）；**任一不符即全量重建，不写兼容读取逻辑**（缓存不该有迁移器）。重建：状态栏"正在重建索引（n/1000）"→ 后台每 100 篇 `await` 让出主线程 → 完成后换新文件；**期间旧索引仍可服务**（0 结果时退回文件名搜索），不做"清空再建"。

### 5.6 原子写入

写 `search-index.json.tmp.<pid>`（同目录确保同卷）→ `fh.sync()` → 旧文件 `rename` 为 `.bak` → `rename(tmp → 正式名)`（Windows 走 `MoveFileEx` + `REPLACE_EXISTING`，同卷原子）。读取失败（`JSON.parse` 抛错/结构缺字段）依次试 `.bak`，再失败则删除重建；绝不就地覆盖写。启动时清理残留 `.tmp.*`（mtime > 1 天或无对应 pid）。

## 6. 向量索引模型（FR-7.4 语义检索）

### 6.1 chunk 切分（结论：结构优先 + 长度护栏，非纯固定字数）

| 参数 | 取值 | 理由 |
|---|---|---|
| 主边界 | H1/H2/H3 标题层级 | 笔记短（2 KB ≈ 1100 汉字），标题边界即语义边界；固定字数会把标题与其正文切散，命中后难定位 |
| 目标长度 | 约 **320 汉字**（≈ 480 token） | 量化版按 `n_ctx` 2048 配置，留余量避免静默截断 |
| 硬上限 | **480 字符**（超出在句号/换行处再切） | 过长稀释主题 |
| 下限 | **120 字符**（不足与下一同级块合并） | 短块向量噪声大，标题块单独成块几无检索价值 |
| 重叠 | **64 字符**（仅硬切分时） | 覆盖跨块句子 |
| 前缀 | 每块前拼 `"{title} / {headingPath}\n"` 再送模型 | 继承文档与章节语境 |
| 不切 | frontmatter | 元数据会污染语义，标签已由关键词路覆盖 |

### 6.2 维度与存储（结论：**二进制**）

维度 **768**（nomic-embed-text-v1.5 原生；Matryoshka 可裁 512/256，本项目**不裁**——1000 篇规模存储成本可忽略，不拿质量冒险）。`vectors.bin` 为定长记录 `768 × Float32 = 3072 B`，顺序与 `chunks[]` 一一对应，文件头 16 B（magic `QNV1` + 维度 + chunk 数 + 版本）。**不选 JSON**：768 维转文本约 8–10 KB/chunk，3000 块 ≈ 25 MB 且需逐条 `JSON.parse`；二进制 9.2 MB，一次 `readFile` + `Float32Array` 视图即用，**零解析**。可重建数据无"人类可读"需求。

```json
// vectors.meta.json
{ "schemaVersion": 1, "formatVersion": 1, "dim": 768, "count": 3000,
  "model": { "id": "nomic-embed-text-v1.5-q4km", "quant": "Q4_K_M", "sha256_12": "<构建期核验>" },
  "rootHash": "9c1f2ab3d4e5",
  "chunks": [{ "i": 0, "path": "工作\\2026-11-17-2231.md", "mtime": 1763389271000,
    "heading": "周会要点 / 阻塞项", "offset": 412, "len": 318,
    "hash": "sha1:5f2c…", "vecOff": 0 }] }
```

### 6.3 相似度与融合排序

**余弦**：写入与查询两侧先 L2 归一化，余弦退化为点积（3000 块 ≈ 2.3 M FLOPs，< 5 ms）。阈值 `cos ≥ 0.62` 入选（`config.ai.semanticThreshold` 可调 0.5–0.8），取 top 20。**与 MiniSearch 合并**：两路分数量纲不同（BM25 式无界分 vs 0–1 余弦），**不做线性加权**，用 RRF（k=60）：`score(doc) = Σ 1/(60 + rank_list(doc))`（每篇取其最佳 chunk 的 rank）；并列次序 = 关键词命中数 → `pinned` → `mtime` 降序。UI：默认"全部"页按 RRF 排序并标来源（「关键词」/「相关」）；独立"相关"页**只放语义结果**（FR-7.4 要求并列展示）且显示所在章节标题。AI 关闭（FR-7.9）时语义路不可用，"相关"页不渲染，退化为单路。

### 6.4 失效机制

| 变更 | 处理 |
|---|---|
| 文件 `mtime`/`size` 变 | chunk 标 `stale` 重切；新 chunk 按 `sha1(headingPath + "\n" + 归一化文本)` 比对，**hash 相同直接复用旧向量**（省大部分推理） |
| 删除 / 移入 `.trash` | 记录删除，`vectors.bin` 标记待压缩（写入时整块重排，不原地打洞） |
| 重命名 | 复用（hash 未变），仅更新 `path` |
| 切分算法 / 维度 / `formatVersion` 变 | 全量重建 |
| 模型（id / 量化 / sha256）变 | 全量重建（元数据 `model` 不匹配即判定） |
| 笔记根切换 | 换 `rootHash` 命名空间 |
| 模型缺失或 AI 关闭 | 只清 `stale` 不阻塞；启用后按队列续做（每批 8 chunk，空闲时让路） |

## 7. 配置 schema（`config.json`）

## 8. 最近打开与草稿

**最近打开**：`recent: [{ path（相对 `<ROOT>`，`/` 归一为 `\`）, openedAt（ISO 8601） }]`；容量 `recentMax` 默认 20（FR-5.7），超出按 `openedAt` 截最旧；笔记成功打开后按 `path` 去重置顶。清理：读取时用目录树扫描集合惰性剔除不存在项（不额外 `stat`）；切换笔记根即清空（相对路径失效）；重命名/入回收站的条目失效剔除。**不存正文、摘要或标题全文**（标题由索引补，缺失时显示文件名）。

**崩溃草稿**：位置 `%APPDATA%\QuickNotes\drafts\<sha1(相对路径)[:16]>.json`；格式 `{ path, content, baseMtime, cursor:{line,ch}, savedAt, appVersion }`；写入时机 = 有未保存内容且（面板失焦收起 / 每 30 s / 保存失败兜底），写前 800 ms 防抖；恢复时不自动覆盖磁盘——仅当 `savedAt > mtime` 且内容不同才提示"恢复 / 丢弃"；清理：保存成功即删、恢复或丢弃即删、7 天过期、> 50 份按 `savedAt` FIFO 淘汰、切换目录不删。**它是唯一含正文的非笔记文件**（NFR-4 显式例外）：明文、位于 `%APPDATA%`、仅异常路径存在、成功即删，`editor.crashingDraft=false` 可完全关闭，设置页须明示。

## 9. 回收站（FR-5.5）

结构**保留原相对路径**并按删除日期分桶：`<ROOT>\.trash\<YYYYMMDD>\<原相对路径>`（删 `工作\周报\2026-11-17.md` → `.trash\20261117\工作\周报\2026-11-17.md`）。保留相对路径使恢复一步归位；日期分桶使保留期清理只需整目录删。同日重名加 `-2`。保留期 **30 天**（常量，暂不暴露配置）：启动时 + 每 24 h 删除 `< today-30d` 的日期桶，清理是**真删除**，设置页"回收站"入口须写明保留期。恢复：列出条目（原路径 + 删除时间 + 大小）→ 目标被占用时**不覆盖**，二选一（另存为 `原文件名-restored.md` / 取消）；成功后触发该文件索引增量更新并从 `recent` 剔除。`.trash` 不被索引器与向量构建器扫描、不出现在目录树（FR-5.6）、不计入笔记数；空桶清理后删空目录。

## 10. 模型文件与校验

### 10.1 模型清单

| modelId | 模型 | 量化 | 字节数 | sha256 前 12 位 | 用途 | 档位 |
|---|---|---|---|---|---|---|
| `qwen3-0.6b-q4km` | Qwen3-0.6B | Q4_K_M | **396 705 472** | `<构建期核验>` | 润色/续写/标题摘要（低配档） | 8–16 GB 默认；完整版内置 |
| `qwen2.5-1.5b-q4km` | Qwen2.5-1.5B-Instruct | Q4_K_M | **986 048 768** | `<构建期核验>` | 同上（高质量档） | ≥16 GB 可选；按需下载 |
| `nomic-embed-v15-q4km` | nomic-embed-text-v1.5 | Q4_K_M | 约 **84 MB** | `<构建期核验>` | 语义检索（768 维） | 启用 AI 即需要 |

> **sha256 占位符的处置（fail-closed）**：上表 `sha256 前 12 位` 的 `<构建期核验>` 由 `scripts/fetch-models.mjs` 在构建期从 ModelScope `repo/files` API 的 `Sha256` 字段读取并写入 `models.lock.json`，**文档内不硬编码**以避免漂移。构建脚本对以下两种情况**直接失败退出**：① `models.lock.json` 中仍含 `<构建期核验>` 字面量；② 下载或内置的 gguf 实际 sha256 与 lock 不符。这与 `03-架构设计文档.md` 的「含占位符即构建失败」约束一致。

来源 ModelScope（官方 sha256 随文件清单返回，FR-7.8）；计划仓库 `Qwen/Qwen3-0.6B-GGUF`、`Qwen/Qwen2.5-1.5B-Instruct-GGUF`、`nomic-ai/nomic-embed-text-v1.5-GGUF`，文件名以仓库实际列表为准。

> **sha256 列不臆造**：由 `scripts/fetch-models.mjs` 在构建机抓 ModelScope 清单写入 `resources\models.lock.json`（`{modelId, repo, fileName, size, sha256}`）；**清单含占位符或字节数与实测不符则构建失败**（fail-closed）。发布产物必须来自填全的 lock，运行期校验以它为准。

### 10.2 本地存放与命名

```
%LOCALAPPDATA%\QuickNotes\models\
├─ models.lock.json                  # 复制自 resources（只读基准）
├─ qwen3-0.6b-q4km\Qwen3-0.6B-Q4_K_M.gguf + verify.json
├─ nomic-embed-v15-q4km\             # {sha256,size,verifiedAt,source:"download|bundled"}
└─ .staging\                         # 下载/复制中的 .part，成功 rename 出门
```

文件名**保留上游原始名**（不改成 `model.gguf`）便于人工核对与手动放置；目录名用 `modelId`，一模型一目录避免同名互撞。

### 10.3 校验流程与失败处理

① 下载/复制完成先比 `size`（不符立即退出，不必算完哈希）；② 流式 `sha256`（0.6B 约 1–2 s，1.5B 约 4 s）与 lock 比对；③ 通过则写 `verify.json` 并 `rename` 到正式目录（原子）；④ 失败：网络中断保留 `.part` 供断点续传，**校验失败必删**，写 `ai.lastError={code:"E_HASH_MISMATCH", at, stage:"verify"}`，UI 给可读原因 + 手动放置路径与期望大小 + 重试，同模型连续失败 2 次后不再自动重试；⑤ 启动时 `verify.json` 缺失或更旧于 gguf 则后台重校验（不阻塞启动），不过即视为缺失、置灰 AI 入口并给原因。

### 10.4 内置与按需下载共用同一位置

优先级 **本地已校验 > 安装包内置 > 网络下载**：完整版把 0.6B 放 `resources\models\`（`asarUnpack`）；启用 AI 时若 `%LOCALAPPDATA%` 已有同 modelId 且校验通过 → 直接用，**不复制不下载**；否则从内置复制到 `.staging` → 校验 → 落位（`source:"bundled"`）→ 再失败才下载。两侧共用同一 `models.lock.json` 与同一 sha256 判据，**内置文件同样校验**（安装包损坏/被杀软改写都能挡住）。用户手动把 gguf 丢进 `models\<modelId>\`，下次启动按 lock 校验通过即用（FR-7.8 的"手动放置说明"落在这一层）。

## 11. 数据迁移与兼容

`config.schemaVersion` 升级走 §7 的顺序纯函数并备份；`index.formatVersion` 升级直接全量重建（索引是缓存，不做逐版本迁移器）。笔记根切换（FR-5.9）：**只切索引命名空间**，旧目录文件一字不动，`recent` 清空、`window` 保留，旧命名空间留最近 3 套（LRU）。多显示器拔插（FR-1.6/1.7）：① 恢复时校验矩形与任一 `workArea` 交集面积/自身面积 ≥ 0.1 才算可见，否则回落主屏右侧垂直居中；② `scaleFactor` 与当前屏不同则按 **DIP 坐标**迁移（不按像素搬），迁移后再校验一次；③ 球与面板独立校验（球可落回而面板回主屏）。网络盘/OneDrive：① 检测 UNC（`\\`）或路径含 `OneDrive`/`Dropbox`/`坚果云` → 黄条警告"外部事件可能延迟，索引降级为 60 s 轮询"；② 增设 60 s 兜底巡检（全量 `stat`，只比 mtime/size）；③ 云占位文件（`OFFLINE`/`RECALL_ON_DATA_ACCESS`）读取抛错则跳过并标 `skipped`，**不触发云端下载**（防一次检索把整个云目录拉下来）；④ mtime 落不可信窗口走 §5.4 快速指纹兜底。降级安装：配置只读（§7）、索引重建、模型按 lock 重校验且未知 modelId 只提示不删文件。

## 12. 数据安全与隐私（NFR-4 / NFR-5）

**绝不落盘到 `config.json`**：正文、正文片段/摘要、选中文本、搜索结果文本、检索查询原文、标签完整词表。配置只允许路径、枚举、数字、布尔、时间戳。

**日志约定（强制）**：允许 `ts`/`level`/`event`/相对 `path`/`bytes`/`ms`/`count`/错误 `code`；禁止正文、命中片段、用户输入、剪贴板内容、完整错误栈（只记 `code` + 首个 `at`）。形态如 `2026-11-17T22:40:11Z INFO index.upsert path="工作\2026-11-17-2231.md" bytes=2048 ms=3`；查询只记 `query.len=12 hits=7`，**不记 query 本身**。兜底：`console` 重定向与未捕获异常对消息截断（≤120 字符）并剔除引号内文本；开发期 `debug` 也不打印正文（用 `bytes`/`hash` 代替）。

**清理时机**：索引/向量按损坏或 `rebuildOnExit` 重建，`rootHash` 第 4 套起 LRU 删；`.trash` 启动时 + 每 24 h 清 >30 天桶；草稿保存成功即删 / 7 天 / 50 份 FIFO；日志启动时按 `retainDays`；`.staging` 清 >24 h 孤儿 `.part`；关闭 AI 卸载推理上下文（FR-7.9）。

**已知边界（须明示，不隐瞒）**：① `storedFields.body` 与 `vectors.bin` 含正文派生数据（明文），是"检索离线可用"的必然代价——位于用户 `%APPDATA%`、随用户 ACL、可随时删后重建；不加密（加密会让 25 ms 的启动反序列化变慢，密钥同样落盘，收益有限），需要更强隐私可用 `rebuildOnExit` 或手动清理。② 草稿是唯一含正文的临时件（§8）。③ 索引不写笔记目录，故把 `<ROOT>` 拷给别人或同步网盘不会泄漏索引；反之拷走 `%APPDATA%\QuickNotes` 会带出索引中的正文片段。

## 附录：不变量清单（实现与评审共用）

1. `<ROOT>` 内除 `.md`、`assets/`、`.trash/` 外，应用不创建任何文件（含临时与锁文件）。
2. 非笔记文件一律"临时文件 + fsync + rename"，不留半截文件。
3. 索引记录 `formatVersion` / `engine` / `tokenizer` / `rootHash`，任一不符即重建而非兼容读取。
4. 向量元数据 `model` 指纹不符即全量重建，绝不混用不同模型的向量。
5. 配置与日志不出现正文；删除只进 `.trash`；标签解析先剥代码块且 URL 的 `#` 永不成为标签；frontmatter 解析失败降级为正文，不报错不改写。
