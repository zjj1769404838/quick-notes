# 05 交互重构设计（v0.2 · 零摩擦）

> 依据：三路独立调研（零摩擦产品做法 / 用户真实抱怨 / 现有实现审查）+ 用户 2026-11-18 拍板
> 上游：`01-需求文档.md`（功能契约）、`02-UI-UX设计文档.md`（视觉规格）

## 一、为什么要改

用户实测反馈「交互不太人性化」。三路调研的交叉结论：

| 维度 | 行业最优（有出处） | 本项目现状 | 差距 |
|------|------------------|-----------|------|
| 到「光标在输入区」 | 1 步 1 键：flomo `Ctrl+N`、Drafts `⇧⌘2`、Apple 快速备忘录 `Fn+Q` | 点球 → 空状态 → 点「＋新建」→ 60ms 后聚焦 = **3 步** | 多 2 步 |
| 必填字段 | flomo 明确拒绝标题；Drafts「without fiddling folders, naming」 | 新建强写 `# \n\n`，光标前摆一个空标题待删 | 多 1 次删除 |
| 保存 | 隐式保存；Drafts「关窗不丢文本」 | 失焦弹「未保存请按 Ctrl+S」 | 误导焦虑 |
| 删除/改名 | 应用内完成 | 调原生 `confirm/prompt` → 面板自己消失 | 像崩溃 |
| 冷启动 | Logseq 直接停在今日页；快速备忘录回到上一条 | 永远回「开始记录」空状态，`recent` 只写不读 | 老用户每天多一步 |

用户抱怨排序（Reddit / V2EX / GitHub issues 交叉）：**① 快（拿起就能记）② 找得到 ③ 不丢 ④ 别逼我组织 ⑤ 别打断心流**。功能数量不在其中。

## 二、用户拍板的三项决策

| 编号 | 决策 | 说明 |
|------|------|------|
| D15 | **两层结构：快速捕捉窗 + 主面板** | 热键唤出小窗，即写即走；需要管理时点球开主面板 |
| D16 | **每次都要能输文件名** | 捕捉窗顶部有文件名框，**预填时间戳**；不改就用时间戳，改了用你的名字。光标默认在正文，`Alt+T` 跳到文件名框 |
| D17 | **标题与正文分两个框** | 标题框在上（可空），正文框在下且自动获得焦点 |

## 三、捕捉窗规格（新增）

### 3.1 形态
- 尺寸 `480×260` DIP，居中于鼠标所在屏幕（不是贴边），置顶 `floating`
- 无边框（`frame:false`）、半透明阴影、圆角 12、失焦**不销毁**
- 唤起方式：全局热键 `Ctrl+Alt+N`（原「新建笔记」语义改为「快速捕捉」）；点悬浮球单击也是唤起捕捉窗
- 主面板入口改为：双击球 / 托盘「打开主面板」/ 捕捉窗内 `Ctrl+Enter` 后的「展开」按钮

### 3.2 布局（从上到下）
```
┌─────────────────────────────────────┐
│ [文件名: 2026-11-18-1908        ] ✎ │  ← 预填时间戳，Alt+T 聚焦
├─────────────────────────────────────┤
│ [标题（可留空）                  ]  │  ← 可选，回车跳到正文
├─────────────────────────────────────┤
│                                     │
│  （正文输入区，自动获得焦点）        │  ← CodeMirror，Markdown
│                                     │
├─────────────────────────────────────┤
│ 已保存 · 12 字        ⌘↵保存并关闭  │  ← 状态栏
└─────────────────────────────────────┘
```

### 3.3 键位（硬约束）
| 按键 | 行为 | 依据 |
|------|------|------|
| `Enter` | **换行**（绝不提交） | flomo/Thino 一致：回车换行，避免误发 |
| `Ctrl+Enter` | 保存并关闭捕捉窗 | Drafts `⌘↩` |
| `Esc` | 关闭捕捉窗，**内容保留**（下次唤起恢复） | Drafts「关窗不丢文本」 |
| `Alt+T` | 光标跳到文件名框 | 本产品特有（用户要能改文件名） |
| `Tab` | 正文内缩进；在文件名/标题框内跳到下一个框 | |

### 3.4 保存语义（隐式）
- 正文停止输入 600ms → 自动写盘，状态栏显示「已保存」
- 文件名框改动 → 失焦时改名（冲突则加 `-2`），失败提示但**不丢内容**
- 关闭窗口 / 失焦 / 切换应用 → 强制 flush，不弹任何「未保存」提示
- 主进程退出前 flush（已有 `requestFlush` 复用）

### 3.5 首次唤起
- 若未完成 onboarding，捕捉窗顶部显示一条：「笔记存在 D:\...\QuickNotes ｜ 换目录」，点「换目录」才弹选择器
- **不再强制**先选目录才能写（用默认目录先写，随时可搬）

## 四、主面板要改的（20 项）

### P0（直接导致放弃使用）
| 编号 | 问题 | 改法 |
|------|------|------|
| U1 | 删除/改名调原生 `confirm/prompt`，弹窗导致面板失焦被收起，像崩溃 | 改面板内联确认条 / 行内改名输入框；弹窗期间 `setPanelUnsaved(true)` 锁定收起 |
| U2 | 标签筛选是空壳（`void tagFilter` 丢弃），点了没反应 | 树按 tag 过滤；无匹配显示「0 篇」 |
| U3 | 冷启动永远回「开始记录」空状态，`recent` 只写不读 | 空状态改为「继续上次：xxx」+ 最近 5 篇直达 |

### P1（明显烦躁）
| 编号 | 问题 | 改法 |
|------|------|------|
| U4 | 从树/搜索打开笔记不聚焦编辑器，键盘打字丢失 | `openNote` 成功后统一 `focus()` |
| U5 | 热键被占用时提示发给尚未创建的面板 → 提示丢失 | 写系统通知 + 设置页常驻显示注册状态 |
| U6 | 点球只「显示」不切换；面板无关闭按钮 | 点球 toggle；标题栏加 `✕`；`Esc` 收起 |
| U7 | 打字后 800ms 内切走会弹「未保存」误导提示 | 自动保存完成后主动收起；文案改「正在保存…」 |
| U8 | 单栏下目录树常驻占 260px，写作区只剩约 260px | 树默认折叠成一行，点开才展开 |
| U9 | 不能建文件夹、不能移动笔记 | 树内「＋新建到此目录」+ 拖拽移动 |
| U10 | 误删后应用内无恢复入口 | 设置页「最近删除」+ 一键恢复 |
| U11 | 拖到屏幕中间的球无法复位 | 球右键/托盘加「重置位置」 |
| U12 | Onboarding 里 `root.set` 失败无任何提示 | 失败 toast + 保留当前页 |

### P2（小瑕疵）
U13 搜索命中后不滚动到命中行 · U14 球右键无菜单 · U15 `crashingDraft` 是死配置 · U16 删除当前笔记后不自动打开相邻篇 · U17 AI 关闭时「相关」tab 应隐藏 · U18 换目录时不 flush pending 保存 · U19 首行标题自动改名未实现 · U20 空状态文案无引导

## 五、验收标准（可执行）

1. **从按热键到能打字 ≤1 步**：`Ctrl+Alt+N` → 捕捉窗出现且光标在正文（自动化测试断言 `document.activeElement` 在 `.cm-content`）
2. **不输入任何文件名也能保存**：直接写正文 → 600ms 后磁盘出现 `YYYY-MM-DD-HHmm.md` 且内容正确
3. **改了文件名就按你的名字存**：填「会议记录」→ 磁盘出现 `会议记录.md`
4. **`Enter` 只换行不提交**：断言正文行数 +1、窗口仍可见
5. **`Esc` 后内容不丢**：写一半 Esc → 再唤起 → 内容还在
6. **删除不弹原生窗**：断言行内确认条出现、面板始终 `isVisible()`
7. **冷启动显示上次笔记**：有 `recent` 时断言空状态含「继续」
8. **标签筛选生效**：点 tag → 树只剩含该 tag 的笔记
9. **所有新增交互均可用键盘完成**（Tab 顺序连续、焦点环可见）
